# 帧与流程规范

## 0. 范围与状态

规定组件的划分、骨架与应用的边界、帧流程与骨架规则。
平台服务语义见 `contract.md`，数据词汇见 `vocabulary.md`，约束见 `constraints.md`。
声音逻辑为预留：其组件、帧流程、钩子在本规范中仅占位，**不**构成当前契约。

## 1. 组件与分工

### 1.1 组件

框架含两个组件（声音逻辑预留）：

- **主逻辑**：推进世界状态；
- **渲染逻辑**：由状态快照产出画面。

组件之间**必须**只通过平台提供的通道（信箱、队列）联系；**禁止**直接访问对方的内部状态。

### 1.2 骨架与应用的边界

每个帧流程由**骨架**与**应用**两部分构成：

- **骨架**（框架负责）：帧流程中与平台服务的全部交互——读取输入、取发管道、要交缓冲；
- **应用**（钩子，应用负责）：纯行为——推进状态、绘制、混音。

应用**禁止**直接调用平台服务；应用与平台的接触**必须**只经由骨架。
应用钩子的接口见 §3，帧流程内每步的执行方见 §2。

## 2. 帧流程

每步标注执行方：【骨架】= 框架执行，【应用】= 应用钩子执行。

### 2.1 逻辑帧（主逻辑被驱动一次）

| # | 步骤 | 执行方 |
|---|---|---|
| 1 | 经输入读取取得一次输入采样 | 骨架 |
| 2 | 执行逻辑，推进一拍世界状态，产出状态快照与事件 | 应用 |
| 3 | 将状态快照发布到信箱 | 骨架 |
| 4 | 将事件逐条发出到队列（预留） | 骨架 |

### 2.2 画面帧（渲染逻辑被驱动一次）

| # | 步骤 | 执行方 |
|---|---|---|
| 1 | 从信箱取用最新状态快照 | 骨架 |
| 2 | 请求一块可写渲染内存 | 骨架 |
| 3 | 以快照为输入绘制 | 应用 |
| 4 | 提交画面 | 骨架 |

### 2.3 声音帧（预留）

排空队列事件、触发与混音、提交声音块。不在本规范范围内。

## 3. 应用钩子

本节规定应用**必须**提供的行为接口。方法名与精确签名为暂定，语义为契约。

### 3.1 逻辑钩子

- 输入：一次输入采样（见 `vocabulary.md`）。
- 行为：推进一拍世界状态。
- 产出：① 一份状态快照，供骨架发布到信箱；② 零条或多条事件，供骨架逐条发出到队列（预留）。
- 产出机制**待定**（返回值 / 访问器 / 输出参数），但**必须**满足：同一逻辑帧内产出的全部事件由骨架逐条交付，**禁止**被合并或覆盖。
- 世界状态**必须**为逻辑钩子私有；渲染逻辑与声音逻辑**禁止**访问。

### 3.2 渲染钩子

- 输入：① 一份状态快照；② 一块可写渲染内存（生命周期见 `contract.md`）。
- 行为：按快照在内存中绘制。
- 约束：**禁止**读取快照与渲染内存以外的任何状态；**禁止**跨帧持有渲染内存指针。

### 3.3 声音钩子（预留）

不在本规范范围内。

## 4. 骨架规则

1. 帧流程内**必须**为一次行为：**禁止**包含循环与等待；循环与等待**必须**由宿主承担。
2. 各帧节奏**必须**互相独立：框架**禁止**对逻辑帧与画面帧的频率比作任何假设。
3. 调用方向**必须**只向下：渲染逻辑与声音逻辑**禁止**回调主逻辑；平台服务**禁止**包含应用逻辑。
4. 组件间的一切交互**必须**发生在帧流程内。
5. 组件**禁止**跨帧持有平台交付的资源指针（渲染内存的生命周期见 `contract.md`）。

## 5. 时序与并发

逻辑帧与画面帧**可以**由宿主在不同并发体分别驱动，也**可以**在同一并发体顺序驱动；本规范在两种情形下**必须**同时成立。

## 6. 验收

1. 帧流程无循环与等待：逐帧流程走查可验。
2. 节奏独立：任意驱动频率比下，画面帧**必须**只呈现已发布的最新快照。
3. 方向只向下：依赖方向走查可验。
4. 骨架/应用边界：应用源码中**禁止**出现平台服务调用，编译隔离可验（见 `constraints.md`）。

## 7. 非目标

不规定组件内部算法、不规定驱动频率、不规定调度方式、不规定钩子的精确签名。
