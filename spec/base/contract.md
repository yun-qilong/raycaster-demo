# 平台契约

## 0. 范围与状态

规定平台**必须**提供的服务及其语义。平台实现方式不在本规范内；应用侧使用方式见 `frame.md`。
方法名为暂定（待定），语义为契约。

## 1. 服务清单

| 服务 | 接口（暂名） | 使用者 | 说明 |
|---|---|---|---|
| 输入读取 | `sample()` | 主逻辑（经骨架） | 提供一次输入采样 |
| 信箱 | `publish()` / `acquire()` | 主逻辑发布、渲染逻辑取用（均经骨架） | 承载状态快照 |
| 队列 | `emit()` / `tryPop()` | 主逻辑发出、声音逻辑取用（预留） | 承载事件 |
| 渲染内存 | `writable()` | 渲染逻辑（经骨架） | 一块可写的画面内存 |
| 画面推送 | `push()` | 渲染逻辑（经骨架） | 接走绘制完成的画面 |
| 时基 | `now()` | 宿主 | 时间读数 |

音频服务预留。

## 2. 语义契约

### 2.1 输入读取 `sample()`

- 前置：由逻辑帧骨架发起请求。
- 后置：返回的输入采样**必须**反映请求时刻的输入设备状态。
- 平台**禁止**主动推送输入。

### 2.2 信箱 `publish()` / `acquire()`

- 语义**必须**为覆盖：任何时刻**必须**至多保留一个状态快照值；发布**必须**覆盖旧值。
- 单次发布与单次取用**必须**各自原子；调用方**禁止**自行加锁或进入临界区，原子性**必须**由平台实现保证。
- 稳定性：取用交出的快照，自交出起至本次画面帧结束，**禁止**被后续发布修改；达成手段**可以**是拷贝，也**可以**是独占。
- 边界：信箱为空（尚无发布）时，取用**必须**返回"无快照"，且输出参数**必须**保持不变；组装**可以**在启动时发布初始快照以保证首帧可绘制。
- 快照规模约束见 `vocabulary.md`。

### 2.3 队列 `emit()` / `tryPop()`

- 语义**必须**为逐条：发出的事件**禁止**被覆盖丢弃；取用**必须**按发出顺序逐条交付。
- 单次发出与单次取用**必须**各自原子；调用方**禁止**自行加锁。
- 容量**必须**有界；满时**禁止**阻塞发出方；**应当**丢弃最旧事件并累计丢弃计数供观测。

### 2.4 渲染内存 `writable()`

- 后置：返回的内存**必须**可容纳一整帧像素，且**禁止**正被画面传输持有。
- 生命周期：**仅在本次画面帧内有效**；帧结束后调用方**禁止**继续持有或访问。
- 像素格式由组装确定；同一组装内**必须**前后一致。

### 2.5 画面推送 `push()`

- 前置：内存为本次画面帧经 `writable()` 所得，且已完成绘制。
- 返回：**必须**返回是否收下（收下 / 通道忙）。
- 行为：**必须**不等待、不重试。收下时平台**可以**切换内部缓冲；忙时本帧作废，内部缓冲**禁止**切换，下一画面帧**必须**重新绘制并复用同一块内存。
- 返回值**禁止**参与流程分支，**仅**用于观测统计。
- 不变式：任一时刻，已交出未提交的内存与正在传输的内存**必须**是两块不同内存。

### 2.6 时基 `now()`

提供时间读数供宿主安排节奏；框架**禁止**使用时基。

## 3. 时序与并发

- 服务的原子性**必须**由平台实现保证；应用**禁止**自行加锁。
- 所有权：快照自发布起归信箱；渲染内存在提交前后归平台，仅在画面帧内交渲染逻辑使用。

## 4. 验收

1. 信箱覆盖语义与稳定性：并发场景下快照不出现半新半旧。
2. 画面推送的翻转规则：忙帧之后下一帧复用同一块内存（可观测）。
3. 计数**应当**可读：画面收下/作废计数、事件丢弃计数。

## 5. 非目标

不规定平台实现（拷贝或直通、传输方式、缓冲数量）、不规定调度与优先级。
