# SPI 40MHz 随机故障的调试记录

> **对象**：STM32H743 + 2.8" 240×320 SPI 屏（ILI9341 兼容模块，带 74HC245 缓冲）
> **结论**：随机故障的根源是**线材信号完整性**，不是屏幕控制器行为
> **时间**：控制器侧假设 2026-09-15 ~ 09-17；换线对照 2026-09-20
> **相关**：[根 README](../README.md) ｜ 驱动库 [lcdriv](https://github.com/yun-qilong/lcdriv)

## 1. 背景与目标

最小可用版本的目标是 **~30fps**。这个目标把设计空间卡得很死：全屏 320×240×2B = 153,600B，
`帧时间 = 153600 × 8 ÷ SCK`，40MHz 才对应 30.7ms/帧（≈32.5fps 上限）——即 SPI 必须跑到 40MHz 量级，
没有"降频换稳定"的余量。

## 2. 现象

40MHz 下随机故障频发，共同特征是**同一份代码时而正常、时而全坏**：

- 大面积写入随机丢数据（表现为"背景暗白"等）
- 清屏后首块区域异常（当时称"首笔数据被吞"）
- 显示状态被破坏（黑底变白等）
- 偶发花屏

决定性特征是**不可复现性**：与"改了什么"关系不大，上电/重启时机不同，结果就不同。

## 3. 控制器侧的假设与处置

| 假设方向 | 处置 | 验证状态 |
|---|---|---|
| 读屏 ID 不可靠、读操作破坏显示状态 | 改为不依赖 ID；显示流程规避读操作 | 未复验，不作因果依据 |
| 初始化缺电压/时序配置组 | 补全配置组 | 未复验；配置补全本身仍保留在驱动中 |
| 软件 CS 场景下 SPI NSSP 脉冲模式误配 | 关闭 NSSP 脉冲 | 配置保留至今（软件 CS 本应关闭，属配置正确性） |
| 开机首笔数据被吞 | 顺序倒转实验定位到"第一笔"，首块写两遍 | 未复验，不作因果依据 |

部分处置确实改变了现象（例如关闭 NSSP 后大批量丢数据收敛），但**残留故障始终无法用控制器行为解释**。
更关键的是：当时**没有"已知良好基线"**——同一块屏、同一份固件换个时刻表现就不同，因此任何"改了就变好"
的观察都无法排除偶发巧合，也无法证明因果。

## 4. 转向线材：假设与对照实验

**物理依据**：40MHz 对应 25ns/bit。20cm 杜邦线在这个边沿速率下已处于信号完整性边缘——反射、串扰、
边沿劣化都可能导致屏侧采样偶发出错。

**验证代价**：换线需要采购，到货等了两天。

**对照设计**：只换线，**代码与固件完全不动**（单变量）。把 20cm 杜邦线换成 10cm 28 芯线后：

- 同一份 DMA 双缓冲固件立即完全稳定：连续运行 9 分钟以上（17000+ 帧）无漂移、无花屏
- 传输侧帧率 32.3fps，约 100% 达成 30.7ms/帧 的理论上限
- 历史"偶发错像素、拿起就闪"一类现象同批消失

## 5. 结论

1. 随机故障的根源是**线材信号完整性**，不是控制器行为。
2. 40MHz 是**满足需求的工作点**，不是实测出的面板上限：目标在 40MHz 已达成，换线后未重做频率爬坡。
3. 本文中来自控制器侧的结论，凡未经换线后复现的，只作为排查记录，**不作因果依据**。

## 6. 沉淀的规则

- **先建立已知良好基线，再谈归因。** 没有基线时，"外设怪癖"与"线路故障"无法区分，任何假设都能被偶发现象"验证"成立。
- **单变量对照优于继续增加假设。** 只换线、代码不动，一次实验即可定性；在控制器侧继续加假设，只会累积不可靠结论。
- **把物理层放进假设列表。** 高速总线的随机错误，先查信号完整性（线长、回流、阻抗、连接器），再查协议与外设。
- **配置正确性与故障根因分开记。** 软件 CS 场景关闭 NSSP 属配置规范，不因"当时问题没解决"而被否定，也不能反过来当成根因。

## 7. 复现建议

如果同类板子在某个 SPI 频率下出现随机错误、且与代码改动无关：

1. 用固定图案（如彩条）在当前接线下反复上电，确认错误是否随机分布；
2. 换更短/更好的线（并检查地回流与连接器），**代码保持不变**；
3. 若换线后立即稳定，说明此前测到的"频率上限"很可能属于线材，而不是器件本身。
